# AGENTS.md — правила работы с репозиторием `apc-speech`

Этот документ описывает архитектуру, инварианты, обязательные проверки и правила внесения изменений в сервис `apc-speech`.

## 1. Назначение и архитектура сервиса

`apc-speech` — автономный локальный микросервис распознавания русской речи, диаризации и семантического анализа телефонных звонков и коротких голосовых запросов для платформы наружной рекламы.

Основные компоненты:
- `app/api/` — HTTP API (FastAPI, все рабочие маршруты под `/v1/`), статика дашборда (`/dashboard`, `/voice`), служебные ручки (`/health`, `/ready`, `/metrics`).
- `app/asr/` — локальное распознавание речи (`faster-whisper` / `T-one` ONNX), VAD, препроцессинг `ffmpeg`/`ffprobe`, нормализация текста (`RussianTextNormalizer`).
- `app/diarization/` — разделение спикеров в стерео и моно (CAM++ d-vectors + классификация ролей `manager`/`client`).
- `app/llm/` — порт семантического разбора (`port.py`), локальный адаптер (`local_adapter.py`: rule-based в профиле `small`, `llama.cpp` Qwen 2.5 7B в `local-full`), внешний адаптер (`external_adapter.py`, выключен по умолчанию), фабрика (`factory.py`).
- `app/pii/` — маскирование персональных данных (`PiiMasker`: телефоны, e-mail, карты, паспорта, ФИО).
- `app/workers/` — асинхронные воркеры Redis Streams (`long_audio_processor`, `fast_voice_search`, `callback_dispatcher`).
- `app/db/`, `alembic/` — PostgreSQL (SQLAlchemy Async + миграции Alembic).
- `app/storage/` — S3/MinIO (`s3.py`).
- `app/queue/` — Redis Streams (`redis_streams.py`).

## 2. Жёсткие инварианты (не нарушать)

1. **Никаких внешних ASR/VAD.** Аудио обрабатывается строго локально и никогда не покидает сервер. В коде и зависимостях не должно быть клиентов внешних STT-сервисов. Проверяется автоматически: `scripts/guards/no_external_asr.py`.
2. **Внешний LLM — только за портом и выключен по умолчанию.** `LLM_EXTERNAL_PROVIDER_ENABLED=false` по умолчанию; при включении туда передаётся исключительно маскированный текст после `assert_no_leaked_pii`.
3. **Никаких ПДн, текстов расшифровок и секретов в логах и метриках.**
   - Не логировать сырой текст расшифровок, номера телефонов, e-mail, токены и секреты.
   - В необработанных исключениях логировать только тип исключения (`type(exc).__name__`), не сырое сообщение с возможными ПДн.
   - Проверяется автоматически: `scripts/guards/no_pii_in_logs.py` и `gitleaks`.
4. **Сетевая изоляция воркеров.** `worker-long`, `worker-fast`, `llm-runtime` работают в изолированной сети `backend` без выхода в интернет (egress). Скачивание по внешним URL выполняет `api`, доставку исходящих callback'ов и интеграционных вебхуков — `worker-callback`.
5. **Безопасность входных данных.**
   - Любой загружаемый файл считается враждебным: проверять лимит размера и заголовки (`ffprobe`), вызывать внешние бинари только массивом аргументов (без `shell=True`).
   - Все внешние URL (загрузка аудио, callback'и, вебхуки) проходят SSRF-валидацию (`validate_ssrf_url` / `validate_callback_url`).
   - Секреты и токены — только через переменные окружения; в `.env.example` значения пустые или тестовые заглушки.
6. **Изоляция данных по `namespace`.** Все запросы к БД, S3 и Redis должны учитывать `namespace` и проверять права токена (`require_scope`, `verify_namespace`).

## 3. Контракт API и стиль кода

- Источник правды по HTTP-контракту — `openapi.yaml` (OpenAPI 3.1). При изменении ручек обновлять `openapi.yaml` и контрактные тесты.
- Единый формат ошибок (`AppError`): `{"error": "snake_case_slug", "message": "Текст по-русски", "details": {...}}`.
- Заголовок `X-Request-Id` принимается от клиента или генерируется, возвращается в ответе и прокидывается в структурированные логи (`structlog`).
- Сообщения для пользователя и документация — на русском языке; идентификаторы, слаги, код — единообразно на английском.
- Форматирование и линтинг: `ruff` (настройки в `pyproject.toml`, длина строки 100, Python 3.12).
- Не блокировать event loop FastAPI синхронным I/O (`boto3`, `subprocess`, DNS) — использовать `asyncio.to_thread` или асинхронные клиенты.
- Метрики Prometheus не должны содержать неограниченных значений в лейблах (использовать шаблон маршрута, а не сырой `request.url.path` с UUID).

## 4. Обязательные проверки перед коммитом / PR

Запуск полного набора проверок:

```bash
make check
```

Включает:
- `uv run ruff check .` — линтер;
- `uv run ruff format --check .` — форматтер;
- `uv run python scripts/guards/no_external_asr.py` — запрет внешних ASR;
- `uv run python scripts/guards/no_pii_in_logs.py` — запрет ПДн и текстов в логах;
- `uv run python -m openapi_spec_validator openapi.yaml` — валидация OpenAPI;
- `APP_ENV=development DEV_TOKEN=dev-token uv run pytest tests/ -q` — юнит- и интеграционные тесты;
- `gitleaks detect --no-banner --redact` — поиск секретов.

Изменения считаются готовыми только при зелёном прогоне линтера, guard-скриптов и тестов.
