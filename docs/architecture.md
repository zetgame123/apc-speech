# Архитектурный Design Document сервиса `apc-speech`

## 1. Контекст и цели

Сервис `apc-speech` — автономный микросервис платформы наружной рекламы, предназначенный для:
1. **Пакетной обработки аудиозаписей телефонных разговоров** (до 3 часов) с получением таймированного транскрипта, разделением спикеров (`manager` / `client`), маскированием ПДн, расчётом акустических речевых метрик и структурированным семантическим анализом (сущности наружной рекламы, таксономия, чек-лист менеджера).
2. **Синхронного голосового поиска** (аудио $\le 60$ с $\to$ текст за $\le 2{,}5$ с) для интерфейса подбора рекламных конструкций на карте.
3. **Сводной аналитики и кластеризации тем** по накопленным звонкам и пачкам текстовых запросов без аудио.

### Ключевые архитектурные принципы
* **Strictly Local ASR**: распознавание речи (VAD, ASR, диаризация, нормализация) работает **только на нашем сервере**. Аудиофайлы никогда не покидают контур сервиса. В кодовой базе отсутствуют клиенты к внешним провайдерам ASR.
* **Privacy-First & Ports/Adapters**: семантический разбор по умолчанию локальный (`local-full`). Внешний LLM-провайдер изолирован за интерфейсом-портом, отключён по умолчанию и физически может получать только деперсонализированный (PII-masked) текст.
* **Dual-Engine Profiles**:
  * `small` (2 vCPU / 4 GB RAM, CPU-only): VAD, ASR, диаризация, маскирование, детерминированные речевые метрики, эмбеддинги и кластеризация.
  * `local-full` (8 vCPU / 32 GB RAM или GPU $\ge 12$ GB): весь функционал `small` плюс локальный LLM-рантайм (7B–14B) для глубокого семантического анализа.
* **Dedicated Fast Lane**: изоляция синхронного voice search от тяжелых пакетных задач на уровне очередей, воркеров и пула ресурсов.

## 2. Границы сервиса и интеграционный контракт

Сервис не имеет прямого доступа к базе данных платформы (Laravel) и не хранит бизнес-логику управления заказами.
Взаимодействие осуществляется по HTTP REST API:
* **Платформа $\to$ `apc-speech`**:
  * `POST /v1/voice/search` (синхронный, $\le 2{,}5$ с).
  * `POST /v1/jobs/upload` или `POST /v1/jobs/by-url` (асинхронный, `202 Accepted` с `job_id`).
  * `GET /v1/jobs/{job_id}` (опрос статуса).
  * `GET /v1/calls/{call_id}/transcript` и `GET /v1/calls/{call_id}/analysis`.
  * `POST /v1/texts/analyze` (анализ и кластеризация текстов без аудио).
  * `DELETE /v1/data/delete` (каскадное удаление по звонку, участнику или периоду).
* **`apc-speech` $\to$ Платформа**:
  * `POST {callback_url}`: вебхук с результатом завершения обработки, подписанный `HMAC_SHA256("{timestamp}.{raw_body}", secret)`.

## 4. Спецификация ASR-пайплайна

1. **Validation & Security**:
   * Проверка magic-bytes и метаданных через `ffprobe` в песочнице с ограничениями ресурсов ядра (`rlimit`).
   * Защита от SSRF при скачивании по URL (DNS-pinning, блокировка private RFC 1918 / loopback / cloud metadata IP).
2. **Preprocessing (FFmpeg)**:
   * Преобразование любого входного кодека в PCM 16-bit 16 000 Hz.
   * Нормализация громкости по стандарту EBU R128 (`loudnorm`).
   * Для стерео: аппаратный сплит каналов на два независимых потока (`ch_0` и `ch_1`).
3. **Anti-Hallucination VAD**:
   * `Silero VAD v5` (ONNX): отсечение тишины, музыки ожидания и шума.
   * `faster-whisper`: параметры `no_speech_threshold=0.6`, `compression_ratio_threshold=2.4`, `condition_on_previous_text=False` (предотвращение зацикливания галлюцинаций).
   * Ранняя детекция автоответчиков / IVR: при обнаружении голосовой почты в первые 15 секунд звонок размечается `is_answering_machine=true`, ресурсоемкий LLM-разбор прерывается.
4. **Chunking & Stitching**:
   * Разрез длинных аудио (до 3 часов) на фрагменты $\le 30$ с по точкам пауз.
   * Перекрытие (overlap) 0.5 с и выравнивание слов по динамическому программированию для устранения дублей.
5. **Prompt Hinting / Hotwords**:
   * Передача специализированного словаря наружной рекламы и городов в `initial_prompt` (точность распознавания терминов $\ge 90\%$).
6. **Inverse Text Normalization (ITN)**:
   * Нормализация размеров («3х6»), временных интервалов («15 с»), сумм («150 000 руб.»), дат и телефонных номеров.
7. **Diarization & Role Mapping**:
   * Stereo: маппинг по метаданным каналов (`manager` / `client`).
   * Mono: извлечение d-векторов спикеров (CAM++ ONNX) + кластеризация + эвристики приветствия и речевых маркеров.
8. **Deterministic Speech Metrics**:
   * Вычисление долей речи спикеров, количества перебиваний, пауз и темпа речи (слов в минуту) строго по временным меткам слов, без участия LLM.
9. **PII Masking**:
   * Маскирование телефонов, e-mail, банковских карт, паспортных данных и имен перед сохранением публичного транскрипта и передачей в LLM.

## 5. Хранение данных и безопасность

* **PostgreSQL 16 + `pgvector`**:
  * Изоляция данных по столбцу `namespace`.
  * Полнотекстовый поиск для русского языка (`to_tsvector('russian', ...)`).
  * Векторные эмбеддинги тем обращений и HNSW-индекс.
* **MinIO (S3)**:
  * Закрытые bucket'ы без публичного доступа.
  * Независимый retention: аудио удаляется через 14 дней, транскрипты хранятся 365 дней.
* **Каскадное удаление**:
  * Эндпоинт `DELETE /v1/data/delete` выполняет полное физическое удаление данных звонка/клиента/периода из MinIO и PostgreSQL.

## 6. Архитектурный дизайн WebSocket-стриминга (Real-Time Streaming ASR)

Согласно требованиям ТЗ (раздел «Желательно: Стриминг по WebSocket с частичными гипотезами»), ниже приводится спецификация протокола, жизненного цикла соединений, буферизации и архитектуры потокового распознавания речи в реальном времени.

### 6.1. Архитектура и компоненты потокового шлюза

```
+-------------------------------------------------------------------------------+
| Client Browser / Mobile WebRTC / Telephony Gateway                            |
+-------------------------------------------------------------------------------+
     |                                                                   ^
     | 1. ws(s)://host/v1/voice/stream                                   |
     |    Binary: PCM16 chunks (100–250ms)                               | 4. JSON: partial &
     |    Text: Control events (start/pause/stop)                        |    final hypotheses
     v                                                                   |
+-------------------------------------------------------------------------------+
| FastAPI WebSocket Connection Handler                                          |
| - Authentication handshake (Token query/header validation)                    |
| - Backpressure guard (Drop / Warning if audio buffer > 3.0s)                  |
| - Session lifecycle & cleanup                                                 |
+-------------------------------------------------------------------------------+
     |                                           ^
     | Audio frames                              | Partial transcripts
     v                                           |
+--------------------+                  +--------------------+
| Streaming VAD      |                  | Rolling Buffer &   |
| (Silero VAD / ONNX)|                  | Hypothesis State   |
| - Voice Activity   |                  | - Ring buffer      |
| - Speech Cutoff    |                  | - History context  |
+--------------------+                  +--------------------+
     |                                           |
     | Trigger on speech                         | Audio window
     v                                           v
+-------------------------------------------------------------------------------+
| Low-Latency Streaming ASR Engine                                              |
| - Model: faster-whisper small / streaming transducer                          |
| - KV-Cache reuse & prompt caching across chunk boundaries                     |
| - Emits: partial interim hypothesis (every 200–400ms)                          |
| - Emits: final stabilized utterance upon VAD pause (>= 450ms)                  |
+-------------------------------------------------------------------------------+
```

### 6.2. Спецификация WebSocket-протокола

* **URL эндпоинта**: `ws://<host>:<port>/v1/voice/stream` или `wss://...`
* **Query-параметры рукопожатия**:
  * `token` / `auth_token`: Bearer токен аутентификации.
  * `namespace`: Пространство изоляции данных (по умолчанию `default`).
  * `language`: Язык распознавания (`ru`, `en`, `auto`).
  * `sample_rate`: Частота дискретизации входного PCM (по умолчанию `16000`, поддерживаются `8000`, `16000`, `48000`).
  * `interim_results`: Флаг отправки промежуточных нестабилизированных гипотез (`true` / `false`, default `true`).

#### Входящие сообщения от Клиента к Серверу
1. **Бинарные фреймы (Binary Frames)**:
   * Непрерывный поток сырых аудиосэмплов PCM 16-bit Little-Endian, моно, 16 кГц.
   * Рекомендуемый квант передачи: 100–250 мс (3200–8000 байт на фрейм).
2. **Текстовые фреймы (JSON Control Events)**:
   * **Старт / Настройка сессии**:
     ```json
     {
       "action": "start",
       "sample_rate": 16000,
       "language": "ru",
       "vocabulary_hints": ["биллборд", "ситилайт", "диджитал суперсайт", "Ленинградский проспект"]
     }
     ```
   * **Принудительный сброс буфера (Flush)**:
     ```json
     {
       "action": "flush"
     }
     ```
   * **Завершение речи**:
     ```json
     {
       "action": "stop"
     }
     ```

#### Исходящие сообщения от Сервера к Клиенту (JSON)
1. **Промежуточная гипотеза (`partial_transcript`)**:
   Отправляется клиенту каждые 200–400 мс во время говорения для мгновенного отображения «живого» ввода:
   ```json
   {
     "event": "partial_transcript",
     "text": "аренда биллборда на Ленинском",
     "stability": 0.82,
     "timestamp": 1.45
   }
   ```
2. **Стабилизированный сегмент (`final_transcript`)**:
   Отправляется при обнаружении устойчивой паузы в речи ($\ge 450$ мс) или получении `stop`/`flush`:
   ```json
   {
     "event": "final_transcript",
     "text": "Аренда билборда на Ленинском проспекте.",
     "start": 0.20,
     "end": 2.15,
     "confidence": 0.94,
     "words": [
       {"word": "Аренда", "start": 0.20, "end": 0.65, "probability": 0.96},
       {"word": "билборда", "start": 0.70, "end": 1.20, "probability": 0.95},
       {"word": "на", "start": 1.22, "end": 1.35, "probability": 0.99},
       {"word": "Ленинском", "start": 1.38, "end": 1.80, "probability": 0.93},
       {"word": "проспекте", "start": 1.82, "end": 2.15, "probability": 0.92}
     ]
   }
   ```
3. **События VAD (`speech_start` / `speech_end`)**:
   Информируют клиентское приложение о появлении или окончании речевого сигнала (для анимации микрофона):
   ```json
   {"event": "speech_start", "timestamp": 0.2}
   {"event": "speech_end", "timestamp": 2.15}
   ```
4. **Результат поискового запроса (`search_query`)**:
   Сформированный и нормализованный текст запроса для поиска конструкций:
   ```json
   {
     "event": "search_query",
     "raw_text": "аренда биллборда на ленинском",
     "normalized_text": "аренда билборда на Ленинском проспекте",
     "extracted_entities": {
       "format": ["билборд"],
       "location": ["Ленинский проспект"]
     }
   }
   ```

### 6.3. Буферизация, Backpressure и отказоустойчивость
* **Rolling Audio Ring Buffer**: входящие бинарные чанки складываются в кольцевой буфер размером до 30 секунд.
* **Backpressure Management**: если обработка отстает от сетевого ввода более чем на 3.0 секунды (перегрузка CPU), сервер отправляет сообщение `{"event": "warning", "message": "buffer_overrun"}` и сбрасывает старейший несформированный сегмент.
* **Auto-reconnect & Clean-up**: при разрыве TCP-соединения WebSocket буфер немедленно освобождается, незавершённые дескрипторы закрываются без утечки памяти.

## 7. Интеграции и расширения

### 7.1. Коннектор телефонии Битрикс24
* **Эндпоинт**: `POST /v1/integrations/bitrix24/webhook`
* **Протокол**: Слушает событие `ONVOXIMPLANTCALLFINISHED`, извлекает `RECORD_URL`, метаданные сотрудника и клиента, ставит задачу в очередь `STREAM_LONG_JOBS`.
* **Запись в CRM**: По завершении транскрибации и семантического анализа формирует структурированный комментарий (итог, тип обращения, договоренности, тональность, расшифровка) и отправляет через REST API `crm.timeline.comment.add` в таймлайн связанной сделки или лида.

### 7.2. Event-Driven S3 Watcher (`scripts/s3_inbox_watcher.py`)
* Автоматически отслеживает поступление новых файлов в `raw-audio/inbox/`.
* При обнаружении файла регистрирует запись в БД (`Call`, `Job`, `AudioObject`), перемещает файл в хранилище вызовов `calls/{call_id}/audio.wav` и ставит задачу в Redis Streams.
* Обеспечивает автономную пакетную загрузку без необходимости прямого вызова HTTP API сторонними скриптами.

### 7.3. Безопасность прямого скачивания через S3 Presigned URLs
* Эндпоинт `GET /v1/calls/{call_id}/audio?presigned=true&expires_in=3600` возвращает клиенту подписанную прямую ссылку на MinIO/S3.
* Предотвращает перегрузку API-шлюза тяжелым медиа-трафиком при воспроизведении аудиозаписей в браузере или мобильном приложении.
