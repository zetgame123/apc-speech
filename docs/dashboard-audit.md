# Аудит мини-дашборда

Дата: 2026-10-15. Статус: только чтение и запуск, код и конфигурация не менялись.
Окружение проверки: живой стенд `docker compose` (project `apc_small`), API на `http://localhost:8000`,
профиль `local-full`, Chromium 152 headless для скриншотов. Все данные — синтетика из репозитория
(`data/evaluation_suite/sample_dialogue_01_telephony_8k.wav`), фейковых данных нет.

Требование-источник: `docs/brief.md` § «Желательно» — список звонков с фильтрами; прослушивание
с синхронной подсветкой расшифровки и говорящими; разбор с чек-листом; сводка тем и менеджеров;
кластеры запросов. Пункт плана: W1 (статус `[ ]`, не выполнен).

## 1. Архитектура и файлы

Бэкенд — один файл, без шаблонизатора:

- `app/api/dashboard.py:14-27` — `GET /`, `/dashboard`, `/ui`, `/dashboard-modern`, `/ui-modern`
  отдают файл `app/static/dashboard-modern.html` как есть (`HTMLResponse(content=f.read())`,
  fallback на `index.html`). Подключено в `app/main.py:268`.
- `app/api/dashboard.py:30-40` — `GET /dashboard-classic`, `/ui-classic` отдают
  `app/static/index-classic.html` (fallback `index.html`).
- Сама HTML-страница **открыта без токена** (нет `Depends(verify_auth)`), БД/Redis/MinIO для неё
  не нужны, но на уровне compose `api` стартует после postgres/redis/minio/migrate/model-downloader.

Статика (три файла, ~82–89 КБ каждый, без сборки — чистый HTML+CSS+JS, отдаётся самим api):

| Файл | Строк | Роль |
|---|---|---|
| `app/static/dashboard-modern.html` | 1930 | основной, раздаётся с `/dashboard` |
| `app/static/index.html` | 1916 | почти идентичен modern (отличие — только 2 блока `getUserMedia`: `dashboard-modern.html:962-969,1573-1582` с шумоподавлением против `{audio:true}` в `index.html:962,1568`, плюс ~96 строк CSS-скина `index.html:190-286`) |

Фактически это **три копии одного кода** (~3×1800 строк копипасты) — правится в трёх местах.
Тестов на JS нет вообще (см. §5).

Как запускается: `docker compose up`, api — `uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1`
(`docker-compose.yml:149-153,197-198`). Проверено живьём 2026-10-15: все 7 алиас-роутов отдают 200
(`/` и `/dashboard*` — 89092 Б, `/dashboard-classic` и `/ui-classic` — 82349 Б).

Что умеет UI (две вкладки, `dashboard-modern.html:323-334`):

  кластеризация через `POST /v1/texts/analyze`.

Ручки, которые дёргает JS (все — относительные `/v1/*`, `getHeaders()` = `Authorization: Bearer`):

## 3. Дефекты и костыли (файл:строка, `dashboard-modern.html`)

**Блокеры (ломают безопасность или вводят в заблуждение):**

- B1. XSS через распознанный текст голосового поиска — `1721-1728`: ASR-текст (`data.text`,
  данные с микрофона — враждебные по определению) вставляется через
  `voiceTextResult.innerHTML = formattedText` без `escapeHtml` (подсветка терминов делается
  `replace` поверх сырого текста). `<img onerror=…>` выполнится. Там же `1664`: `err.message`
  в `innerHTML` без экранирования.
- B2. Молчаливое глотание 401/ошибок: `fetchVoiceHistory` (`1740-1755`) — `console.warn` + return,
  пустая таблица неотличима от «нет данных»; `loadCallResults` (`1059-1074`) — нет проверки
  `res.ok`, при ошибке UI остаётся от прошлого звонка. Подтверждено живьём скриншотом (§2).

**Серьёзные:**

- S1. Пагинации нет: `limit=15` захардкожен (`1400`), `next_cursor` игнорируется, «показать ещё» нет —
  на сотнях звонков старые недоступны вообще. Рендер — полная перестройка `tbody` (`1407,1428`).
- S2. Фильтров/поиска нет (см. §2 п.1), хотя сервер всё поддерживает — расхождение с brief.
- S3. Сводки тем/менеджеров и экспорта CSV нет в UI (см. §2 п.4) — расхождение с brief.
- S4. Несоответствие подписи и кода записи: подпись «Лимит: до 60 секунд» (`646`), а автостоп —
  через 6 с (`1605-1612`: `remain = 6.0 - elapsed`, `setTimeout 6000`). Та же цифра 6 с в `index.html`,
  `index-classic.html`.
- S5. Хрупкий рендер анализа: `seg.start.toFixed` без проверки типа (`1163,1184`) — битый сегмент
  роняет весь `renderChat`; `data.job_id.substring(0,8)` без null-check (`1025`); `0` трактуется
  как «-» в метриках (`1382-1385`: `ratio ? … : '-'`, `wpm || '-'`); при `duration==0` RTF фальшивый
  `0.25x (~4x быстрее)` (`1699`).
- S6. Polling-интервал 1500 мс не останавливается при смене namespace/уходе (`1033-1057`); при `failed`
  старые результаты не очищаются; при сетевой ошибке — бесконечное «Опрос статуса...».
- S7. `openArchivedCall('${safeId}')` через `innerHTML` (`1415-1423`): `escapeHtml` (`&#039;`)
  декодируется HTML-парсером обратно до создания JS-контекста — шаблон уязвим по построению
  (сегодня `call_id`=UUID, практически неэксплуатируемо; чинится `data-*` + `addEventListener`).
- S8. Три файла-копипасты (§1): любое исправление нужно вносить в 3 места.

**Мелкие:**

- M1. Термины подсветки захардкожены (`1722`: 15 строк) + `new RegExp(t,"gi")` без экранирования.
- M2. `texts` для кластеризации могут содержать `undefined/""` (`1821`), проверки нет.
- M3. Пустые состояния без спиннеров/aria (`442-447,602-606,788-790,812-817`); кнопки экспорта
  кликабельны до готовности (защита только `disabled`, `902-909`).
- M4. Производительность подсветки: `querySelectorAll('.word-span')` + перебор всех слов на каждый
  `timeupdate` (`879-890`) без throttle/rAF — на часовом звонке тысячи span; `Math.max(...arr.map)`
  (`1091`) — spread на большом массиве.

## 4. Безопасность и соответствие запретам

- **Аутентификация:** HTML открыт всем (`dashboard.py`, без `Depends`). Токен живёт только в DOM
  (`317`: `value="dev-token"`, `313`: `value="demo_outdoor_msk"`; ни `localStorage`, ни
  `sessionStorage` не используются). Передача — только `Authorization: Bearer` header (в query токена
  нет — хорошо); исключения без токена: `GET /health`, `GET /v1/voice/sample-audio`. Полный функционал
  требует `read`+`write`; `dev-token` в non-production даёт `admin+write+read` (`security.py:70-71`).
  Дефолт `dev-token` прямо в открытом HTML (`317`) — любой открывший страницу в dev уже держит
  admin-способный токен в поле ввода.
- **XSS:** `escapeHtml` есть (`833-841`) и покрывает сущности/нарушения/рекомендации/историю/кластеры,
  стенограмма и саммари идут через `innerText` — но два пути без экранирования, см. B1
  (`1721-1728`, `1664`) + слабый шаблон S7.
- **Внешние ресурсы:** ровно 4 CDN-URL, без SRI/crossorigin (`8,9,11,827`: bootstrap CSS+JS,
  bootstrap-icons, `unpkg.com/wavesurfer.js@7` — те же в обоих остальных файлах). Шрифтов Google,
  аналитики, внешних `fetch` нет — весь API same-origin. Но: без интернета дашборд без стилей и плеера
  (локального вендоринга/фолбэка нет); компрометация CDN = выполнение JS в контексте страницы с
  токеном в DOM. Прямое нарушение запрета «аудио не покидает сервер» через дашборд **не обнаружено**
  (аудио идёт через API-стрим, внешних отправок нет).
- **ПД:** дашборд никогда не передаёт `masked=false` (grep — ноль), серверный дефолт `masked=True`
  (`calls.py:63`) — видны только маскированные сегменты. Однако любому держателю `read` без
  дополнительных барьеров показываются: полный текст диалога, `summary/entities/checklist/sentiment`,
  история запросов, примеры в кластерах, `external_id` + `manager_id` в журнале (`1413-1418`).
  Если маскер что-то пропустит в `text_masked/summary/entities` — UI покажет это сразу, переключателя
  «показать немаскированное (admin)» с подтверждением нет.
- **Заголовки:** `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`,
  `Referrer-Policy`, HSTS — **отсутствуют полностью** (grep по `app/` — ноль; единственный кастомный
  заголовок — `X-Request-Id`, `main.py:185`). Дашборд можно встроить в чужой iframe (clickjacking
  действий «Загрузить/Удалить историю/Кластеризация»). CORS: `allow_credentials=True` +
  `allow_methods/headers=["*"]` (`main.py:130-138`), в production `*` — только ворнинг.
- **Скоупы:** читающие ручки дашборда (`calls*`, `voice/history`) — `read`, без rate-limit
  (в `calls.py`/`dashboard.py` нет `Depends(rate_limit)`); rate-limit есть только на
  `voice/search`, `jobs/*`, `texts/analyze`, `integrations/*`. Сам `/dashboard` — без rate-limit.
- **Подпись URL аудио:** presigned-механизм существует (`calls.py:173-209`, `expires_in` 60–86400),
  но дашборд его **не использует** — только прямой стрим `GET .../audio` с Bearer-header → blob →
  временный `blob:`-URL (`1440-1447`, скачивания `1459-1480`). Утечки долгоживущих URL нет, но байты
  гоняются через api-процесс.

## 6. Предложение по доработке

Технология: **оставить как есть** — статические файлы без сборки, отдаваемые самим api.
Основание: дашборд уже работает в этом виде, внешних JS-зависимостей кроме 4 CDN-URL нет,
сборка (npm/vite) добавит тулчейн и артефакты без выгоды для двух вкладок. Единственное вложение —
**завендорить** bootstrap/bootstrap-icons/wavesurfer в `app/static/vendor/` и подключить локально:
убирает зависимость от интернета и снижает риск CDN до нуля. Цена: ~0,5 дня (скачать 4 файла
фиксированных версий, заменить 4×3 URL, проверить `make check` + скриншот); риск — обновления
зависимостей станут ручными (приемлемо для внутреннего инструмента).

Минимальный план (порядок — по тяжести, оценки — pessimistic, всё без изменения API,
`openapi.yaml` **не затрагивается**: все нужные серверные фильтры/сводка/CSV уже есть):

1. B1+B2+basic-заголовки — 1–2 дня: `escapeHtml(cleanText)` до подсветки терминов + escape
   `err.message` (`1664,1721-1728`); явный баннер «401 — проверьте токен/namespace» во всех fetch-ручках;
   `frame-ancestors 'self'`/nosniff через middleware в `main.py`; `data-*` вместо инлайн-`onclick`
   (`1423`). Без API-изменений.
2. S4, S5, S6, M1–M4 — 1–2 дня: честный лимит записи (подпись 6 с для микрофона / 60 с для файла —
   по факту серверного лимита) или убрать автостоп-магию; null-checks (`1025,1163,1184,1382-1385`);
   остановка polling при смене namespace; throttle/rAF подсветки; термины из конфига вместо хардкода.
3. S1+S2 (фильтры+пагинация) — 2–3 дня: инпуты `q/manager_id/inquiry_type/date_from/to` + кнопка
   «Загрузить ещё» по `next_cursor` поверх существующего `GET /v1/calls`. Без API-изменений.
4. S3 (сводка) — 2–3 дня: блок «Сводка» на существующем `GET /v1/analytics/summary` (темы, топ-сущности,
   средние чек-листа, тренды — рендер таблицами, без графических библиотек) + ссылка на существующий
   `GET /v1/analytics/export_csv`. Без API-изменений.
5. Кластеры (добивка п.5) — 1 день: textarea для ручного ввода текстов + кнопка (существующий
   `POST /v1/texts/analyze`, лимит 500). Без API-изменений.
6. Дедупликация трёх HTML в один шаблон/общий JS — 1–2 дня (опционально, можно отложить; уменьшает
   риск рассинхрона S8).
7. Тесты — 1–2 дня: Playwright/Chromium smoke (есть `/usr/bin/chromium`): 200 всех алиасов,
   список с токеном, 401-баннер, escape-проверка на синтетике с `<img onerror>` в тексте,
   скриншоты в `reports/`. Новый эндпоинт не нужен.

Новый эндпоинт (с изменением `openapi.yaml`) не требуется ни для одного пункта: всё упирается
в неиспользование уже существующего API. Единственное возможное расширение — `GET /v1/calls/filters`
(справочник типов/менеджеров для выпадающих списков), но его заменяет хардкод таксономии из
`config/taxonomy.yaml` на фронте.
