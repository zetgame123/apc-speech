## Детали по пунктам

### 0. TONE_THREADS=1 (`reports/c10_threads_default_2026-10-13.json`)
Дефолт задан явно в `app/core/config.py`, `.env.example`, README (масштабирование:
`TONE_THREADS` = числу физических ядер, `OMP_NUM_THREADS=1`). 400 запросов:
503 — 0, p95 ~2,0 с. Быстрее 2,41 с при капе 3 ГГц — решает частота (~4,29 ГГц).

### 3. WER (`reports/wer_golos100.json`, `reports/terms_hints.json`)
Нормализация (регистр, ё/е, пунктуация, числа) + юнит-тесты
(`tests/test_wer_cer.py`). Первые 100 записей манифеста Golos, детерминировано.
Ориентир ≤ 12 % на чистой речи не выполнен ни одним движком
(T-one ближе всех: 16,1 %); по телефонии (≤ 25 %) проходит только T-one
(19,6 %). Подсказки-hotwords у whisper-small почти не влияют
(61,4 % → 63,6 %, до 90 % далеко). T-one быстрее podlodka в ~20 раз
(38 с против 771 с на 100 файлов).

### 4. DER (`reports/der_suite.json`)
30 диалогов 2–5 мин (gTTS, второй голос — pitch-shift, перебивания каждые
~6 ходов, моно/стерео, G.711). Моно: CAM++ + эвристика ролей (28,7 с/файл).
Стерео: энергетический VAD по каналам (мгновенно). Missed stereo ~0,27 —
паддинги TTS-тишины в эталоне генератора, детектор их честно молчит.
Роли: 0,94 моно / 0,98 стерео.

### 5. Типы и сущности (`reports/types_eval.json`)
Набор A — 120 диалогов (все 12 типов × 10, эталон тип + 6 сущностей),
набор B — 25 (иные формулировки, синонимы, multi-intent). Qwen — подвыборка
A каждый 4-й (30 шт.) + весь B; ASR-шум — TTS B → whisper-small → оба адаптера.
Сущности quantity/period/budget/category: F1 = 0,0 — rules жёстко ставит
`target_period`/`product_category` в None, текстовые числительные
(«двести тысяч») скорер не сводит к числам, Qwen поля чаще не заполняет.
Это дефект покрытия, а не метрики — зафиксирован, не припудрен.

### 6. Время (`reports/hour_small_uncapped.json`, `reports/hour_localfull.json`)
Часовка — конкат 15 моно-диалогов DER-набора, ровно 3600 с, 115 МБ.
Первичны server-side цифры (created→updated): small 3431 с / RTF 0,953;
local-full 3456 с / RTF 0,960. Метки стадий квантованы опросом 60 с (±60 с).
8 vCPU не ускоряют: чанки ASR идут столько же — потоки движков от cpuset
не растут. Прогон с капом 3,0 ГГц — не измерено (нет sudo к
`scaling_max_freq`).

### 7. Стоимость (`reports/provider_cost.json`)
Скрипт `scripts/eval_provider_cost.py` (цены задаёт пользователь через
флаги/env). Замерено: 802 prompt + 235 gen токенов на разбор. Реальных
вызовов не было, фактическая стоимость — не измерено.

## Ограничения оценки
- Наборы A/B, DER-30, часовка — синтетика (gTTS, один автор шаблонов);
  2 TTS-голоса вместо живых; оценка оптимистична.
- Golos farfield — короткие командные фразы («салют …»), не диалоги;
  WER на нём ≠ WER на звонках.
- Qwen — подвыборка 30/120 на A (дорого); ASR-шум только на B (25 шт.).
- Частота плавала (3,66–4,29 ГГц, без капа); сравнение small/full —
  в один день, но не одновременно.

## Не измерено (причины)
- Common Voice ru: датасет `mozilla-foundation/common_voice_17_0`
  пуст на Hub (EmptyDatasetError), старые версии удалены; без VPN/другого зеркала.
- Разбор ≤ 30 с на GPU ≥ 12 ГБ: нет GPU на стенде.
- Часовая запись с капом 3,0 ГГц: нет sudo для `scaling_max_freq`.
- Фактическая стоимость провайдера: нет ключа, адаптер выключен.
- 8 vCPU без GPU для разбора (погранично): не замерено отдельно.

## Узкие места
1. Разбор Qwen на CPU: 65 с против 30 с — только GPU решит.
2. ASR часовки (75 % времени) не масштабируется ядрами — смотреть потоки
   faster-whisper/CTranslate2 и чанкинг.
3. worker-long упирается в лимит RAM 2112 МБ (пик 2106) — поднять лимит
   или резать чанки.
4. Сущности period/budget/category/quantity не извлекаются — доработка
   экстрактора (не скорера).
5. Термины с подсказками 64 % против 90 % — hotwords whisper почти не работают.

## Что не получилось
- Ориентиры WER clean (12 %), термины (90 %), разбор 30 с, ускорение ×2
  на 8 ядрах — не достигнуты; причины выше, данные не подгонялись.
- CV ru отсутствует в стенде; кап 3 ГГц и GPU — нет возможности замерить.
