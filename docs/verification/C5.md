# C5. Разбор по JSON-схеме — живая проверка (2026-10-11)

Код: `app/llm/port.py` (`AnalysisModelPort`), `app/llm/local_adapter.py`
(`LocalLlamaCppAdapter`: LLM → `normalize_analysis_dict` → pydantic →
fallback `_analyze_via_rules`), `config/taxonomy.yaml`, `config/checklist.yaml`,
`schemas/analysis_schema_v1.json`; тесты `tests/test_compliance_and_emotions.py`,
`tests/test_api_contract.py::test_structured_analysis_schema_validation*`.

## 1. Rule-fallback на small

Разбор звонка содержит `schema_version: "1.0.0"`, `prompt_version: "v1.2-ru-outdoor"`,
`summary`, `call_result`, `inquiry_type` (по таксономии из конфига), `entities`,
`agreements`, `sentiment`, `manager_checklist`, `deterministic_speech_metrics`.
Тело ответа (без envelope `call_id`) валидно против `schemas/analysis_schema_v1.json`
(`jsonschema.validate`, Draft 2020-12) — проверено скриптом на живом ответе.

## 2. Локальная модель на local-full (Qwen)

`llm-runtime` (llama.cpp server-b4738, Qwen2.5-7B Q4_K_M) поднят в `apc_small`
(`--profile local-full`), веса локальные, сеть `backend` без egress.
Контрольный звонок (`c5_llm_test`): в логах воркера
`POST http://llm-runtime:8080/v1/chat/completions → HTTP/1.1 200 OK` дважды
(разбор + `llm_role_refinement_by_speaker_success`), разбор валиден по схеме.
Ранее (без сервера): 25× `local_llm_call_failed_fallback_to_rules`
(в т.ч. DNS-ошибка) → корректный откат на правила.

## 3. JSON по схеме всегда

Запрос к LLM идёт с `response_format: {type: json_schema}`; ответ чинится
`normalize_analysis_dict` (слаги → enum, дефолты `other`/`info_provided`),
валидируется pydantic `StructuredAnalysis`; любое исключение (сеть, плохой JSON,
схема) → `_analyze_via_rules` (детерминирован, 0 RAM сверх). Внешний адаптер
выключен (`LLM_EXTERNAL_PROVIDER_ENABLED=false`, получает только маскированный
текст — см. C7).
