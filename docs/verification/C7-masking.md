# C7-masking. Маскирование живьём — проверка (2026-10-11)

## 1. `POST /v1/texts/analyze` (найдена и закрыта утечка)

Вход (6 текстов): произнесённый телефон словами, `ivan.petrov@example.com`,
карта `4111 1111 1111 1111` и `4111111111111111`, `паспорт 4510 123456`,
`+7 900 123-45-67`, `8(900)1234567`.

- Было: `representative_queries` и подпись кластера отдавали сырые ПД
  (`"моя почта ivan.petrov@example.com…"`, подпись `"1111 / 900 / …"`).
- Исправлено (`app/api/analytics.py`): кластеризация идёт по маскированным
  текстам — подписи и представители чистые:
  `"Email договора / …"`, `"Карта / вторая / …"`,
  `"моя почта [EMAIL]…"`, `"оплата картой [КАРТА]…"`,
  `"паспорт [ПАСПОРТ]…"`, `"телефон [ТЕЛЕФОН_1] и [ТЕЛЕФОН_2]"`.
  Тест `test_texts_analyze_masks_pii_in_response`. Время ответа 0,9 с.
- Остаток (осознанно): произнесённые словами номера («восемь девятьсот…»)
  в этом endpoint не цифруются — `mask_text` работает с цифровыми формами;
  речевые формы покрывает конвейер звонков (`convert_spoken_phones`, живьём
  `+[ТЕЛЕФОН_1]` в C2).

## 2. Разбор звонка с готовым текстом

Транскрипт звонка хранится в двух колонках (`TranscriptSegment.text_original`
+ `text_masked`, `long_audio_processor.py:324-333` — проектное решение):
`masked=true` → `+[ТЕЛЕФОН_1]`, `masked=false` → сырой `8-900-12-34-56`
(для admin/разбора; наружу — только маскированное, внешнему провайдеру —
`assert_no_leaked_pii`).

## 3. БД и логи

- БД: сырые сегменты лежат рядом с маскированными (см. п.2); жизненный цикл —
  удаление одной ручкой (C7) и сроки хранения (C7-retention).
- Логи api: 0 вхождений `ivan.petrov`, `4111 1111`, `4510 123456` после
  прогона (тела запросов/ответов не логируются; guard `no_pii_in_logs` зелёный).
