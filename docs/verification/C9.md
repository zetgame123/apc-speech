# C9. Задания и callback'и — живая проверка (2026-10-11)

Код: `app/api/jobs.py` (202 + `status_url`, `Idempotency-Key`/хэш-дедуп, 409 при
конфликте ключа), `app/workers/callback_dispatcher.py`
(`RETRY_DELAYS_SEC=[5,15,60,300,900]`, подпись `X-Apc-Timestamp`/
`X-Apc-Signature` пересчитывается на каждую попытку, SSRF-отказ без попыток);
тесты `tests/test_callbacks.py`, `tests/test_jobs_api.py`.

## Проверено живьём

- Статусы/прогресс: `queued → running → succeeded`, `progress 0–100`, шаги
  (`asr_transcription`, …) — на всех заданиях C1/C2.
- Идемпотентность по ключу: повтор upload с тем же `Idempotency-Key` → тот же
  `job_id` (3d07139b… оба раза).
- Идемпотентность по хэшу: тот же файл без ключа (разный `external_id`) → тот же
  `job_id` (eb8d1e48… оба раза).
- Подпись: `sign_callback_payload` (HMAC `"{timestamp}.{raw_body}"`, `sha256=`).

## Юнитами (тайминги живьём не измерить осознанно)

- 5 попыток с задержками ровно [5,15,60,300,900], затем сдача
  (`test_dispatch_callback_retries_five_times_then_gives_up`).
- SSRF-отказ callback без HTTP-попыток (`test_dispatch_callback_ssrf_rejected`).

## Не проверено, причина

Сквозная доставка callback на живой приёмник: приёмник в приватной сети
отклоняется SSRF-защитой по построению, а слать синтетику на публичный
endpoint вне контура нельзя. Путь покрыт юнитами + кодом.
